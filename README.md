# Tiny GPT — Build a Language Model From Scratch

Character-level GPT-style language model built with **Python, PyTorch, and NumPy concepts**.

The model is assembled step by step: tokenization, embeddings, positional information, Query/Key/Value (Q/K/V) projections, causal self-attention, multi-head attention, Transformer blocks, next-character prediction, training, and streamed text generation.

## Features

- **Character-level tokenizer** — converts each unique character into an integer ID.
- **Token embeddings** — learns a vector representation for each character.
- **Learned positional embeddings** — gives the model information about token positions.
- **Query, Key, and Value projections** — Q, K, and V are calculated from the input using trainable linear layers; they are not manually hardcoded.
- **Causal self-attention** — blocks each position from attending to future positions.
- **Multi-head attention** — runs several attention heads in parallel, concatenates their outputs, and applies an output projection.
- **Transformer blocks** — use pre-layer normalization, residual connections, and a feed-forward network.
- **Next-character training** — optimizes cross-entropy loss with automatic backpropagation and AdamW.
- **Autoregressive generation** — generates one character, appends it to the context, and predicts the next character.
- **Streaming terminal output** — generated characters are printed as they are produced.
- **Indian-related example data** — includes small question-and-answer and fact examples about India, alongside AI-related examples.

## Requirements

- Python 3.10 or newer recommended
- PyTorch
- A terminal such as PowerShell, Command Prompt, or a Unix shell
- CPU is sufficient for this small experiment; a supported CUDA GPU may make training faster

Only PyTorch is required by the main script shown in this project. NumPy is useful for the earlier standalone attention exercises, but the final `tinyGPT.py` implementation uses PyTorch operations.

Open PowerShell in your repository directory.

```

.\venv\Scripts\Activate.ps1
```

### 3. Install PyTorch

```powershell
python -m pip install --upgrade pip
python -m pip install torch
```

### 4. Verify the installation

```powershell
python -c "import torch; print(torch.__version__); print('CUDA available:', torch.cuda.is_available())"
```

The script automatically selects CUDA when PyTorch reports a supported GPU is available. Otherwise, it uses the CPU.

## Run the model

From the repository directory, with your virtual environment active:

```powershell
python tinyGPT.py
```

The script will:

1. Build the character vocabulary and encode the text dataset.
2. Split the encoded text into training and validation segments.
3. Create batches of input sequences and next-character targets.
4. Initialize the model parameters.
5. Train the model and print periodic training and validation loss.
6. Generate text from the configured prompts, streaming each character to the terminal.

Training time depends on your CPU/GPU and the configuration.

## How the model works

### 1. Character-level tokenization

Every unique character receives an integer ID. For example, the characters in `hello` are represented by IDs from the vocabulary generated by the script. The mapping is built automatically from the training text.

Character-level tokenization is simple and useful for learning, but it is less efficient than the subword tokenizers used by most modern LLMs.

### 2. Training examples

The model receives a sequence and is trained to predict the next character at each position. The input and target sequences are shifted by one character.

For example:

```text
Input:  hello wor
Target: ello worl
```

### 3. Embeddings and position

The model looks up a learnable embedding for each character and adds a learnable positional embedding. This gives the network information about both token identity and position in the sequence.

### 4. Q, K, and V

Each attention head computes its Q, K, and V matrices from the input representation using separate learned projections:

```python
Q = self.q_proj(x)
K = self.k_proj(x)
V = self.v_proj(x)
```

These are calculated by the network at runtime; the vectors themselves are not hardcoded.

### 5. Causal self-attention

The model compares queries against keys, scales the scores, masks future token positions, applies softmax, and uses the resulting attention weights to combine value vectors:

```text
Q, K, V
  ↓
Scaled query-key scores
  ↓
Causal mask
  ↓
Softmax attention weights
  ↓
Weighted combination of values
```

The causal mask prevents a token from looking at future characters when predicting the next character.

### 6. Transformer block

Each block contains:

- Layer normalization before attention
- Multi-head causal self-attention
- A residual connection around attention
- Layer normalization before the feed-forward network
- A feed-forward network with a GELU activation
- A residual connection around the feed-forward network

The final model stacks multiple Transformer blocks.

### 7. Training

The language-model head produces one logit per vocabulary character. Cross-entropy compares the model's predictions with the correct next-character IDs. PyTorch autograd calculates the gradients, and AdamW updates the trainable parameters.

The main training loop is conceptually:

```text
Get batch → Forward pass → Cross-entropy loss
    → Backpropagation → AdamW update → Repeat
```

### 8. Streaming generation

The generation function starts from a prompt and repeatedly:

1. Feeds the most recent context into the model.
2. Gets logits for the next character.
3. Converts logits into probabilities.
4. Chooses the next character by sampling (or by argmax if greedy decoding is configured).
5. Appends the character to the context.
6. Prints the new character immediately using `flush=True`.

This is **character-by-character terminal streaming**. It demonstrates the basic idea of streaming, but it is not a web-based chat interface or the same server-side streaming protocol used by ChatGPT.

## Training data

The sample corpus contains short examples such as:

- Indian state capitals
- Indian national observances
- Indian landmarks and currency
- A few general facts about India
- Simple AI and attention statements

The code repeats the small corpus to provide additional training iterations. **Repeating examples does not add new information.** A small model may memorize some patterns without learning to answer questions robustly.

### Validation caveat

If the program repeats the complete dataset and only then takes the last 10% as validation data, the validation segment will contain repetitions of examples that also occur in the training segment. Therefore, its validation loss is not an independent measure of generalization. For a more meaningful evaluation, split the original examples first, then repeat only the training examples; keep the validation examples separate and unrepeated.

## Configuration

The following settings control training and model capacity in `tinyGPT.py`:

| Setting | Purpose | Effect of increasing it |
|---|---|---|
| `block_size` | Maximum context length | More previous characters can be considered, with more computation and memory use |
| `d_model` | Token representation size | More feature capacity and more parameters |
| `num_heads` | Number of attention heads per block | More parallel attention mechanisms, within the chosen model dimension |
| `num_layers` | Number of Transformer blocks | More processing depth and more parameters |
| `batch_size` | Number of sequences in each batch | More examples per update, using more memory |
| `max_iters` | Number of training updates | More optimization steps, which may help until overfitting or saturation |
| `learning_rate` | Optimizer step size | Larger values can learn faster but may make training unstable |
| `temperature` | Randomness during generation | Lower values make output more concentrated; higher values make it more random |

The values you use may differ from these examples. Check the configuration section of your script to see the active settings.
